The system

What runs the weekly review

Signals in, a seasonality layer, a rule engine with about thirty guardrails, an agent that investigates what the rules flag, and a second agent whose only instruction is to refute it. A planner reviews what survives, in roughly thirty minutes. The two ways a forecast can be wrong are not symmetric, so cutting and raising follow deliberately different rules.

The full write-up covers the architecture and the results. How I work covers the gate every change goes through. A clean-room version runs the same design on synthetic data, and every rule described on this site is one of its unit tests.

How I work

How I decide a number is real

UNIT

Does the change do what I intended? Checked by hand, offline, before it touches data.

BACKTEST

Is it actually more accurate? Against a period the model cannot see, and against a naive forecast. Mandatory whenever a threshold is being set.

REGRESSION

Did it break anything else? Same data, before and after; only the differences I intended.

SHADOW

Should it ship? Beside the live system, on real weeks, with nothing downstream connected.

Write the judgment down, let the rules settle what they can, and put a person on what they cannot.
