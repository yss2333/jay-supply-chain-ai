# Forecast review — project instructions

A clean-room forecast review on **synthetic data**. Every retailer, item and number is generated by `forecast_review/synthetic.py` or `supply_ops/synthetic.py`. Never present a number from here as a real result.

## Tools (MCP server `forecast-review`, started from `.mcp.json`)

| Question | Tool |
|---|---|
| Which retailers are there? | `list_retailers` |
| What did the rules flag at one retailer? | `review_retailer` |
| Everything about one item | `item_signals` |
| The raw weeks behind a claim | `weekly_series` |
| The deterministic refuter's verdict | `refute` |
| The whole pipeline, every retailer | `weekly_review` |
| Should a retailer use the seasonal curve? | `seasonal_backtest` |
| The rules and parameters in force | `explain_rules` |
| Stock value by excess tier (and the date-filter bug) | `excess_inventory` |
| Stock older than the aging window, write-off list vs over-buys | `aged_stock` |
| Days of coverage, freight route, supplier tier | `coverage_plan` |
| How far ahead a customer's plan can be trusted | `plan_horizon_accuracy` |
| Does a forecast look too good? | `leakage_check` |

## Sub-agents (`.claude/agents/`)

| Agent | Role |
|---|---|
| `retailer-scout` | Investigates one retailer; spawn one per retailer, in parallel |
| `forecast-refuter` | Tries to refute every finding before anything changes |
| `item-investigator` | Deep-dives one item whose signals disagree |

## How a review runs

- **"Review RETAILER_C"**: one `retailer-scout`, then `forecast-refuter` on its findings, then a table of final actions.
- **"Review everything"**: five scouts in parallel, one per retailer, then one refuter over all findings.
- **"Why is C-05 on hold?"**: `item-investigator`.

Finish every review with one line per item: action, size, and the evidence that decided it. Items the refuter marks SUSPECT go to the planner, not into the forecast.

## Operating rules

- Sell-through is the demand signal. Shipments below plan can mean we could not supply.
- Low store in-stock blocks a cut; the item gets a buffer instead.
- A raise needs a second, independent signal. Shipments alone return HOLD.
- Cuts and raises are capped. New items are protected from cuts.
- Never read an unfinished week. Never compare a window that contains a spike without checking the run-rate.
- A confirmed order counts as demand however old its date. Report excess in dollars before shares.
- Read stock from the freshest source before computing coverage.
- A pleasant surprise in a backtest is a reason to test further, not to ship.
